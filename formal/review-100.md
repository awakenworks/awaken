# One-hundred-round formal-verification review

This is the auditable progress ledger for the requested repeated review of the
current code. A round is complete only when it names a concrete production
boundary, classifies which claims are formalizable, records any defect and fix,
and cites executable or machine-checked evidence. Re-reading the same metric
does not count as another round.

The review is intentionally incomplete until all 100 rows are present. The
formal coverage percentage in `coverage.json` measures versioned safety
obligations; it is not a substitute for these repeated review rounds.

## Current classification boundary

Suitable for repository-owned formal verification:

- pure authorization, admission, selection, revision and transition kernels;
- finite lifecycle protocols, crash/retry/CAS/lease state machines and safety
  properties over durable facts;
- in-process lock interleavings with Loom;
- executable Rust-to-TLA trace refinement for production commits.

Not provable end to end from this repository alone:

- eventual or exactly-once behavior of arbitrary networks and third parties;
- database, object-store, Kubernetes, CSI, kernel and container-runtime
  implementation correctness;
- KMS cryptographic implementation/key custody and provider revocation latency;
- LLM semantic quality, sampling behavior, performance and unbounded liveness;
- telemetry delivery/retention and equivalence of separately built Worker-host
  executors.

Those boundaries still require contracts, integration tests, fault injection,
conformance checks, observability and operational drills. They must not be
silently reclassified as machine-proved merely to keep a 100% ratio.
